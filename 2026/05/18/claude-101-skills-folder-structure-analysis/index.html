3. Skills vs Projects

Skills 和 Projects 都能给 Claude 提供上下文，但它们解决的问题不同。

Both Skills and Projects can give Claude additional context, but they solve different problems.

内容类型 / Content type 文档、背景、历史记录、项目资料 / Docs, background, history, project materials 步骤、方法、模板、脚本 / Steps, methods, templates, scripts
典型用途 / Typical use 存放 release 背景、测试计划、需求文档 / Store release context, test plans, requirements 固化 qTest 指标分析流程 / Standardize qTest metrics analysis

4. Project Knowledge、Project Instructions、Skill 的区别

Difference Between Project Knowledge, Project Instructions, and Skills

这三个概念容易混淆。

These three concepts are easy to confuse.

概念 / Concept 适合放什么 / What to put there 示例 / Example
Project Knowledge 项目背景、资料、文档 / Project background, documents, reference materials PowerStore 4.1 release test plan
Project Instructions 这个 Project 内 Claude 的通用行为规范 / General behavior rules inside the Project 所有回答先给结论，再给分析 / Always give conclusion before analysis
Skill 某类任务的固定执行流程 / Fixed workflow for a repeatable task 每次 qTest 分析都计算 Pass Rate / Failure Rate / No Run Rate

判断标准：

Decision criteria:

判断问题 / Question 更适合的位置 / Best location

这是这个 Project 中所有回答都要遵守的风格吗？ / Is this a general response behavior for the whole Project? Project Instructions
这是某类任务每次都要执行的步骤吗？ / Is this a fixed step for a repeated task? Skill
这是某类报告固定的输出结构吗？ / Is this a fixed output structure? Skill / templates
这是可执行代码吗？ / Is this executable code? Skill / scripts

15. 常见误解 / Common Misunderstandings

误解 / Misunderstanding 正确理解 / Correct understanding
Skill = Prompt 不对。Prompt 是一次性请求，Skill 是可复用流程包 / A prompt is one-time; a Skill is reusable
Skill = Project Knowledge 不对。Knowledge 偏资料，Skill 偏执行方法 / Knowledge is information; Skill is procedure
所有内容都应该放进 SKILL.md 不建议。SKILL.md 应保持精简 / Keep SKILL.md concise
references/ 就是 Project Knowledge 不完全是。它是 Skill 内部执行所需规则 / It stores rules needed by the Skill
scripts/ 只是可选，不重要 对计算、解析、文件处理任务非常重要 / Critical for deterministic computation and parsing
templates/ 和 examples/ 一样 不一样。template 是结构，example 是样例 / Template is structure; example is sample output
status mapping 一定放 Project 不一定。通用执行规则更适合放 Skill references / General execution rules fit Skill references
Project 和 Skill 二选一 不对。Project 提供上下文，Skill 提供流程 / They complement each other
Skill 越大越强 不对。边界清晰的小 Skill 更可靠 / Smaller, focused Skills are more reliable

17. 总结 / Summary

Skill 可以理解为一个“小型专业工具包”：

A Skill can be understood as a small specialized toolkit:

对 QA / SDET / DevOps 场景来说，Skill 的价值不是简单地“让 Claude 多知道一点”，而是让 Claude 每次都能按照同一套标准流程执行任务。

For QA / SDET / DevOps, the value of Skills is not simply giving Claude more information. The value is making Claude execute the same task with the same standard workflow every time.

Final mental model:

Do not mix rules into scripts, templates into the entry file, or project background into the Skill.
