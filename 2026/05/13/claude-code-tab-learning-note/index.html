Claude Code Tab 学习笔记：Local、Remote 与三种交互模式

Created2026-05-13|Updated2026-05-13|AI ToolsAgent Workflow
|Word Count:2.6k|Reading Time:9mins|Post Views:

核心结论

Claude Desktop App 里的 Code tab，本质上是把 Claude Code 集成进桌面应用，让 Claude 可以直接进入真实代码项目中工作。

它不只是“聊天式写代码”，而是更接近一个 AI 开发环境：Claude 可以读取代码库、修改文件、运行命令、查看 diff，并通过 git 保留版本，方便回滚。

一句话记忆：

Cowork 偏 information work；Code 偏 software engineering work。

1. Code tab 是什么？

原文：

The Code tab gives you access to the power of Claude Code, running directly inside the desktop app. This gives you a full development environment for building software.

理解：

Code tab 让你可以在 Claude 桌面 App 里直接使用 Claude Code，并获得一个完整的软件开发环境。

关键词：

Expression Meaning 中文理解
Code tab a section/page in the app App 里的“代码”标签页
gives you access to allows you to use 让你可以使用
the power of Claude Code Claude Code 的能力 Claude Code 的开发能力
full development environment complete coding workspace 完整开发环境
building software creating apps/tools/projects 构建软件

这里的重点是 full development environment。它不只是回答代码问题，而是能参与真实开发流程：

  • 读取项目文件
  • 修改代码
  • 运行终端命令
  • 查看 visual diff
  • 使用 git 跟踪版本
  • 必要时启动本地开发服务

2. Claude 在 Code 里能做什么？

原文：

Via Code, Claude works directly in your codebase: reading what’s there, writing and modifying code, running commands.

理解：

通过 Code tab，Claude 可以直接在你的代码库里工作。

它可以做四类事情：

  1. read what’s there：读取已有代码
  2. write code：写新代码
  3. modify code：修改已有代码
  4. run commands：运行命令

这里的 codebase 指的是一个项目的完整代码集合，包括：

  • 源代码
  • 配置文件
  • 测试文件
  • 脚本
  • 文档
  • CI/CD 配置

例如：

  • Hexo 博客源码仓库
  • Python 自动化工具仓库
  • Jenkins polling skill 仓库
  • TUIC monitor 项目
  • 存储系统测试框架项目

这些都可以叫 codebase。

3. Visual diffs、terminal、git 如何理解？

原文：

Visual diffs show what changed, a built-in terminal shows commands as they run, and git tracks every version so you can always roll back.

逐句理解：

原文 中文意思
Visual diffs show what changed 可视化 diff 显示哪些地方被改了
a built-in terminal shows commands as they run 内置终端显示命令执行过程
git tracks every version git 记录每个版本
roll back 回滚到之前版本

diff 是什么？

diff = difference，表示修改前和修改后的差异。

这说明 timeout 从 5 被改成了 10。

在 AI 编程场景中，visual diff 很重要，因为它可以让你快速判断：

  • Claude 改了哪些文件
  • 改动是否符合预期
  • 有没有误删或误改
  • 是否需要接受、拒绝或继续调整

4. Code 和 Cowork 的核心区别

原文：

Where Cowork runs in a contained workspace limited to the folders you share, Code runs directly in your project with full access to your file system, terminal, and development tools.

这是整段最关键的一句话。

理解：

Cowork 运行在受限工作区里，只能访问你共享的文件夹；Code 则直接进入你的项目，并可以使用文件系统、终端和开发工具。

Dimension Cowork Code
Main purpose research, documents, multi-source work software development
Workspace contained workspace real project folder
File access limited to shared folders broader project/file-system access
Terminal not the main focus central capability
Git workflow not core core
Best for reports, analysis, briefs, slides coding, refactoring, testing, debugging

简单记忆

  • Cowork：更适合资料整理、跨来源分析、生成报告、做研究任务。
  • Code：更适合进入 repo，修改代码、运行测试、调试问题、做重构。

从 SDET / DevOps / QA 的角度看：

  • 如果你要 Claude 读会议记录、Slack、邮件、文档并整理结论，使用 Cowork 更合适。
  • 如果你要 Claude 修改 Python 脚本、修 Jenkins integration、跑 pytest、分析 git diff，使用 Code 更合适。

5. Local 模式

原文：

Local: You select a folder on your computer and Claude works directly with those files.

理解：

Local 模式下，你选择电脑上的一个文件夹，Claude 直接操作这个文件夹里的项目。

适合场景：

  • 本地 Hexo 博客项目
  • 本地 Python 自动化脚本
  • 本地测试工具
  • 需要访问本机依赖或环境变量的项目
  • 需要启动本地开发服务并在浏览器预览的项目

优点：

  • 能访问本机工具链
  • 能使用本地终端
  • 能运行本地 dev server
  • 适合贴近真实开发环境

风险：

  • 权限更大
  • 可能接触本地敏感文件
  • 可能运行影响系统状态的命令
  • 需要更谨慎地审查 diff 和 terminal command

6. Remote 模式

原文：

Remote: You connect a GitHub repository and Claude works in a cloud environment.

理解：

Remote 模式下，你连接 GitHub 仓库，Claude 在云端环境中工作。

适合场景：

  • 大型代码库
  • 不想污染本地环境
  • 长时间重构任务
  • 希望会话在关闭 App 后继续运行
  • 希望把开发任务隔离到云端环境

关键词：

Expression Meaning 中文理解
cloud environment cloud-based workspace 云端开发环境
sessions continue sessions keep running 会话继续运行
close the app exit the desktop app 关闭 App
check back later return later to review 之后回来查看

Local vs Remote 简表

Dimension Local Remote
Code location your computer cloud environment
Source local folder GitHub repository
Best for local dev, preview, machine-specific tools larger repo, long-running work, isolated environment
Risk local file/system exposure cloud environment trust and repo permission

7. 三种交互模式

原文：

Three interaction modes let you control how much Claude does on its own.

意思是：

三种交互模式决定 Claude 可以自主做到什么程度。

7.1 Ask Mode

原文：

Ask: Claude proposes every change and waits for your approval.

理解：

Ask mode 下，Claude 每次修改前都会提出建议，并等待你批准。

适合：

  • 高风险项目
  • 生产项目
  • 你还不完全信任 Claude 自动修改代码时
  • 你想通过 review diff 学习代码改动逻辑时

关键词：

Word Meaning 中文理解
propose suggest 提议
approval permission 批准
accept or reject approve or refuse 接受或拒绝

一句话：

Ask mode = Claude 先提议，你批准后才改。

7.2 Code Mode

原文：

Code: Claude applies file changes automatically but checks before running terminal commands.

理解：

Code mode 下，Claude 可以自动修改文件，但在运行终端命令前会先询问你。

适合：

  • 小范围 bug fix
  • 中等风险代码修改
  • 普通开发任务
  • 你愿意让 Claude 自动改文件，但仍想控制命令执行时

一句话：

Code mode = 文件自动改，命令先确认。

7.3 Plan Mode

原文：

Plan: Claude outlines its full approach before touching anything.

理解：

Plan mode 下，Claude 在修改任何内容之前，会先给出完整方案。

适合：

  • 大重构
  • 复杂 bug 分析
  • CI/CD 改造
  • 测试框架设计
  • 存储系统问题排查
  • 需要先明确风险、边界和验证策略的任务

关键词：

Expression Meaning 中文理解
outlines summarizes or lists 概述、列出
full approach complete strategy 完整方法
before touching anything before modifying anything 在动任何东西之前

一句话：

Plan mode = 先计划，再动手。

8. 多会话管理

原文：

You can run multiple sessions across projects and filter them by status and environment.

理解：

你可以在不同项目中同时运行多个 Claude Code 会话，并按状态或环境筛选。

Filter Meaning 中文理解
Active currently running 正在进行
Archived saved but inactive 已归档
Local local machine environment 本地环境
Cloud remote/cloud environment 云端环境

例如你可以同时开：

  • 一个 session 改 Hexo 博客
  • 一个 session 修 Python monitor
  • 一个 session 重构 Jenkins polling skill
  • 一个 session 分析测试框架失败日志

9. 谁可以使用 Code tab？

原文：

The Code tab is available on Pro, Max, Team, and Enterprise users.

理解：

Code tab 面向 Pro、Max、Team、Enterprise 用户开放。

这里的 available on 表示“对某些套餐或平台可用”。

10. 实际使用建议

由于 Code tab 的权限比普通聊天更大，建议采用以下使用策略：

低风险任务

例如：

  • 修改 README
  • 写小脚本
  • 修复 typo
  • 添加注释

可以使用：

Code mode

中风险任务

例如：

  • 修改业务逻辑
  • 添加新功能
  • 修改 CI 配置
  • 改测试框架

建议使用：

Ask mode

高风险任务

例如：

  • 大规模重构
  • 删除文件
  • 修改部署流程
  • 变更认证、token、权限、网络配置
  • 改生产相关脚本

建议使用：

Plan mode → Ask mode → 手动 review diff → 再执行命令

11. 对 SDET / QA / DevOps 的使用价值

对于测试、存储系统、DevOps 和自动化场景，Code tab 的价值不只是“写代码”，更重要的是：

  1. 让 Claude 直接理解真实项目结构
  2. 基于代码上下文修复问题
  3. 运行测试命令验证修改
  4. 通过 diff 审查每一步变化
  5. 通过 git 保留回滚能力
  6. 适合构建长期维护的工具和 skill

典型任务：

  • 修复 pytest case
  • 重构自动化脚本
  • 编写 Jenkins polling tool
  • 添加日志和状态机
  • 生成 README / AGENTS.md
  • 调整 Hexo 博客项目
  • 分析失败测试并补充验证步骤

13. 最小实践流程

如果我要用 Claude Code 处理一个真实项目，我会这样做：

  1. 先确保 git 工作区干净
  1. 用 Plan mode 让 Claude 先说明方案
  2. 确认改动边界
  3. 切到 Ask mode 或 Code mode
  4. 查看 visual diff
  5. 运行测试
  1. 再次查看 git diff
  1. 确认后提交

14. 小练习

请用一句话分别解释下面三个模式：

Mode Your explanation
Ask Claude 先提出修改建议，等用户批准后再改。
Code Claude 可以自动改文件，但运行终端命令前需要确认。
Plan Claude 先给完整方案，不会直接修改任何东西。

15. 总结

这段文字的真正重点不是“Claude 又多了一个 tab”，而是：

Claude 正在从聊天助手变成可以进入真实工程环境的 AI coding agent。

对开发者、SDET、QA、DevOps 来说，关键能力不是让它“回答代码问题”，而是让它：

  • 理解代码库
  • 修改代码
  • 运行命令
  • 展示 diff
  • 保留 git 回滚能力
  • 在 Local 或 Remote 环境中完成工程任务

因此，Code tab 更适合用于真实软件工程；Cowork 更适合用于复杂信息工作。
