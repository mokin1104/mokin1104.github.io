Prompt Components Framework: What Makes a Good Prompt

Created2026-05-08|Updated2026-05-09|AI & Prompt Engineering
|Word Count:2k|Reading Time:8mins|Post Views:

Question Restatement

基于这段内容，详细拆分：一个合适的 Prompt 应该由哪些组成部分构成？

But you may ask, what is a good prompt? Before your next conversation with ChatGPT, consider a few things:

Setting the stage: What is your role and what are your objectives? Is there context about your work that ChatGPT should know about?

Defining the task: What action do you want ChatGPT to take? Do you want ChatGPT to write, analyze, build, or something else?

Specifying rules: What’s the style or tone you want ChatGPT to use? Are there examples that you can attach to show ChatGPT what you’re looking for?

Conclusion

一个高质量 Prompt 可以拆成 8 个核心组成部分：

更简单地说：

告诉模型：你是谁、你要什么、背景是什么、让它做什么、基于什么材料、遵守什么规则、输出成什么样、什么叫做好。

你引用的内容里提到的三部分：

  1. Setting the stage
  2. Defining the task
  3. Specifying rules

是一个很好的基础框架。

但如果想写出更工程化、更稳定的 Prompt，可以把它扩展成下面这个结构。

1. Role：设定角色

作用

告诉模型它应该以什么身份回答。

例如：

中文理解：

你是一位资深存储系统 SDET 和调试导师。

为什么重要

因为不同角色会影响回答角度。

Role Output Bias
English teacher 解释词义、语法、表达
Senior QA engineer 关注测试策略、证据链、风险
DevOps engineer 关注部署、CI/CD、可观测性
Product manager 关注需求、用户、商业价值
Security reviewer 关注风险、权限、攻击面

注意

不要乱设角色。

角色要和任务相关。

2. Goal / Objective：说明目标

作用

告诉模型你最终想达成什么。

例如：

中文：

我的目标是找出最可能的根因，并确定下一步调试动作。

为什么重要

如果没有目标，模型可能只会泛泛解释。

例如你说：

模型不知道你想要：

  • 找根因？
  • 判断是否是环境问题？
  • 写 Jira comment？
  • 判断是否可以 rerun？
  • 生成测试报告？

3. Context：提供背景信息

作用

告诉模型当前场景、业务背景、技术背景、已知事实。

例如：

为什么重要

上下文就是：

a shortcut to understanding your needs

也就是让模型少猜，直接进入有效分析。

好的 Context 应该包含什么

Context Type Example
业务背景 This is for a release-blocking test failure.
技术背景 The environment uses PowerStore and iSCSI.
当前状态 The cluster is free, but the job was not relaunched.
已知事实 No new Jenkins builds were created after 14:15.
限制条件 I cannot access the appliance directly now.

风险

背景不是越多越好。

应该提供和任务相关的上下文，避免把无关材料全部塞进去。

4. Task：定义具体动作

作用

告诉模型你要它具体做什么。

原文里说：

Do you want ChatGPT to write, analyze, build, or something else?

这就是 defining the task。

常见任务动词

Verb Meaning Use Case
explain 解释 学英语、学概念
analyze 分析 日志、文章、问题
summarize 总结 文档、会议、邮件
compare 对比 工具、方案、概念
generate 生成 文案、代码、计划
rewrite 改写 邮件、报告、句子
debug 调试 错误、代码、环境
design 设计 架构、测试方案、状态机
review 审查 PR、方案、英文表达

6. Rules / Constraints：指定规则和限制

作用

控制回答边界、风格、深度和安全性。

原文说：

Specifying rules: What’s the style or tone you want ChatGPT to use?

也就是告诉模型：

你希望它怎么回答，不希望它怎么回答。

常见规则类型

Rule Type Example
风格 Use a formal and concise style.
语气 Be direct and evidence-based.
深度 Explain step by step.
结构 Use Markdown headings and tables.
证据 Cite sources where possible.
禁止项 Do not invent missing facts.
语言 Reply in Chinese, but keep technical terms in English.
受众 Assume I am a junior storage QA engineer.

中文：

一个好的回答应该帮助我判断：是重新跑测试、升级给开发，还是先检查环境。

Good vs Weak Prompt

Weak Prompt

问题：

Gap Why It Hurts
没有背景 模型不知道场景
没有任务深度 不知道要简单解释还是深入分析
没有输出格式 结果不稳定
没有规则 可能泛泛而谈

Better Prompt

这个 Prompt 更好，因为它有：

Component Present?
Context Yes
Task Yes
Rules Yes
Output expectation Yes

Practical Decision Rule

不是所有 Prompt 都需要完整 8 部分。

Task Complexity Prompt Requirement
查一个单词 只需要 task
改写一句话 task + tone
分析日志 context + input + task + evidence rules
写报告 role + goal + context + task + format
设计系统 role + constraints + architecture requirements + success criteria
高风险判断 facts + assumptions + citations + limitations

Final Mental Model

一个好 Prompt 本质上不是“咒语”，而是一个任务说明书。

也就是：

你不是在写神秘命令，而是在给一个能力很强但不了解你具体场景的同事分配任务。
你给的信息越清晰，它越容易稳定交付。
