Linux Sandbox（沙箱）：从 Namespace 到 seccomp 的隔离体系

Sandbox = 对进程的权限、资源、系统调用和可见范围进行限制。

Linux 里的 Sandbox（沙箱）并不是某一个单独的内核功能，而是一种安全隔离机制：把一个进程放进受限制的运行环境里，让它「能看到什么、能访问什么、能调用什么」都受到控制。它通常由多个内核机制组合实现。

Linux 机制 控制什么

其中 Namespace + cgroups + capabilities + seccomp 是容器技术的核心基础。

九、Sandbox 和 VM 的最大区别

容器之间共享 Host Kernel。这也是为什么 Docker 通常启动快、内存开销小，但隔离边界没有 VM 那么强——当 Linux Kernel 出现 container escape 漏洞时，就可能从容器越界到宿主机。

需要更强边界时，业界的做法是把两者叠加：gVisor 用用户态内核拦截 syscall，Kata Containers / Firecracker 则直接给每个容器配一个轻量 VM。

十一、从测试工程角度看：多层防线

把 Sandbox 理解成一个分层结构，测试时更容易定位边界：

测试 Sandbox 时不能只验证「进程能不能启动」，而应该逐层验证边界是否真的生效：

验证维度 探测命令 预期结果
Filesystem escape cat /etc/shadow Permission denied / 文件不存在
Privilege escalation mount /dev/sda /mnt Operation not permitted
Network access ping 8.8.8.8 网络不可达
Syscall restrictions ptrace another_process EPERM 或进程被 kill
Resource exhaustion fork bomb / 内存分配循环 被 cgroups 限制，宿主机不受影响
Device access ls /dev 只有最小设备集
Process isolation ps aux 只看到 sandbox 内进程

每一项都应该被明确控制，而不是「碰巧没发生」。
